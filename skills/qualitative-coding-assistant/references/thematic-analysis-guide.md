# Thematic analysis and qualitative coding guide

## 1. Choosing the approach

| Approach | Coding | Codebook | Inter-rater reliability | Output | Use when |
|---|---|---|---|---|---|
| Reflexive thematic analysis (Braun and Clarke) | Inductive or deductive, interpretive, evolves throughout | No fixed codebook | Not used; reflexivity instead | Themes as patterns of shared meaning | Exploring meaning and experience |
| Codebook thematic analysis (template, framework) | Structured; codebook developed early and applied | Yes | Optional | Themes, often matched to topics | Team projects, policy questions, defined areas |
| Framework analysis | Matrix of cases by themes | Yes | Optional | Charted matrix | Applied health and policy research |
| Qualitative content analysis | Categories from data or theory | Yes | Often reported | Categories, sometimes counts | Describing content systematically |
| Grounded theory coding | Open, then axial or focused, then selective or theoretical | Develops with constant comparison | Not central | Theory of a process | Building theory |
| Interpretative phenomenological analysis | Case by case, then across cases | No | No | Experiential themes | Small homogeneous samples, lived experience |

## 2. The six phases of reflexive thematic analysis

| Phase | Work | Output |
|---|---|---|
| 1 Familiarisation | Read and reread; note initial ideas | Memos |
| 2 Coding | Label meaningful segments across the whole dataset | Coded extracts |
| 3 Generating initial themes | Cluster codes around shared meaning | Candidate themes |
| 4 Developing and reviewing themes | Check against extracts and the whole dataset | Revised themes, thematic map |
| 5 Refining, defining, naming | Write the central organising concept and boundaries of each theme | Theme definitions |
| 6 Writing up | Analytic narrative with extracts | Findings section |

## 3. Codes

| Kind | Describes | Example code for "I stopped asking because nobody ever answered" |
|---|---|---|
| Semantic | What is said | unanswered requests |
| Latent | Underlying meaning or assumption | learned helplessness in help-seeking |
| In vivo | Participant's own words | "nobody ever answered" |
| Process | An action | withdrawing from help-seeking |

Code as many segments as are relevant; one segment can carry several codes. Keep code labels short and specific.

## 4. Codebook entry

| Field | Content |
|---|---|
| Code name | Short label |
| Definition | What the code captures |
| Include when | Criteria with an example |
| Exclude when | Near-misses and which code they belong to |
| Example | A verbatim extract with participant and location |
| Notes | Date added, revisions |

## 5. Theme quality tests

| Test | Question |
|---|---|
| Central organising concept | Can the theme be stated as one idea, not a list? |
| Shared meaning | Do the extracts share a meaning, not only a topic? |
| Distinctness | Is it clearly different from the other themes? |
| Coherence | Do the extracts fit together without forcing? |
| Evidence | Does it draw on several participants, with extracts? |
| Relevance | Does it answer the research question? |
| Boundaries | What does it not include? |

A "domain summary" (everything participants said about topic X) is not a theme in reflexive thematic analysis. Name such summaries as topics if they are used.

## 6. Negative cases

Search for data that contradict each theme. Report them and explain how they refine the theme (a boundary, a subgroup, a condition). They strengthen credibility.

## 7. Agreement when codebooks are used

- Two coders code the same subset (often 10 to 25% of the data) independently.
- Compute agreement per code (Cohen's kappa for two coders) where the approach calls for it.
- Discuss disagreements, revise definitions, and recode.
- Report the procedure, not only the coefficient.

## 8. Saturation and sample adequacy

| Concept | Meaning |
|---|---|
| Code saturation | New interviews add few new codes |
| Meaning saturation | New interviews add little new understanding of existing codes |
| Information power | Smaller samples suffice when the aim is narrow, the sample specific, the dialogue strong, and the analysis case-oriented |

State how the decision to stop collecting was made.

## 9. Writing up

| Element | Guidance |
|---|---|
| Theme heading | Name that conveys the analytic point |
| Opening | The central concept of the theme in two or three sentences |
| Extracts | Two or three from different participants, with identifiers; mark trimming with [...] |
| Analysis | Interpret each extract; do not let quotes speak for themselves |
| Prevalence | Words such as "several", "most" only if counted; avoid percentages for small samples |
| Link | Connect each theme to the research question and to the literature |

## 10. Trustworthiness record

| Strategy | Record |
|---|---|
| Audit trail | Codebook versions, memos, decisions with dates |
| Reflexivity | Researcher position and its influence, kept in a journal |
| Triangulation | Multiple data sources, analysts, or methods |
| Member checking | Participants' responses to interpretations, if used |
| Thick description | Context detailed enough for readers to judge transferability |

## 11. Confidentiality in transcripts

Replace names, workplaces, places, and rare details with bracketed placeholders ([colleague], [hospital]). Keep the key separately and securely. Check that the processing of transcripts, including any software or AI tool, is covered by consent and the ethics approval.
