# Response strategies and phrasing

## 1. Comment types and strategies

| Comment type | Strategy | Opening phrase |
|---|---|---|
| Valid criticism, fixable | Agree, fix, show the change | "We agree. We have <change> (Section x, lines y–z)." |
| Valid criticism, not fixable now | Agree, narrow the claim, state as a limitation | "We agree that <X> would strengthen the work. Because <reason>, we have narrowed the claim to <...> and added this as a limitation (Section x)." |
| Misunderstanding | Clarify, revise the text | "Thank you for raising this; our description was unclear. <Clarification>. We have revised Section x to make this explicit." |
| Request for experiment, feasible | Run it, report numbers | "We ran <experiment>: <result with numbers>. This is added as <Table/Figure>." |
| Request for experiment, infeasible | Explain concretely, offer an alternative | "<Experiment> would require <resource>, which is beyond <...>. Instead, we <alternative>, which shows <...>." |
| Missing reference | Add and position | "Thank you. We now cite <paper> and discuss how our approach differs: <...>." |
| Disagreement on substance | Respectful disagreement with evidence | "We respectfully see this differently. <Evidence: data, citation, or proof>. We have added <text> to make this reasoning explicit." |
| Out of scope | Acknowledge, explain scope, mention as future work | "This is an interesting direction. It lies outside the scope of this paper, which focuses on <...>; we note it as future work (Section x)." |
| Minor or editorial | Fix | "Fixed." or "Corrected throughout." |
| Positive comment | Thank briefly | Only in the opening sentence, not per comment |

## 2. Phrasing to avoid and alternatives

| Avoid | Prefer |
|---|---|
| "The reviewer misunderstood ..." | "Our description was unclear; we have clarified ..." |
| "As clearly stated in the paper ..." | "As described in Section x (now expanded) ..." |
| "This is obvious." | Give the reason in one sentence |
| "We will do this in future work" (for a core request) | Do it, or explain why it cannot be done and narrow the claim |
| Long thanks repeated for every comment | One thank-you at the start |
| Arguing with the score | Address the concerns behind it |

## 3. Prioritising under a length limit

1. Concerns shared by several reviewers.
2. The concern most likely to drive the decision (often the most negative reviewer's main point, or the meta-review).
3. Factual misunderstandings that can be corrected briefly.
4. New results that change the picture.
5. Minor points, compressed.

## 4. Conference rebuttal mechanics

| Item | Practice |
|---|---|
| Length | Character or word limits are enforced; count before submitting |
| Format | Plain text or Markdown with tags such as [R1], [R2]; some platforms allow per-review replies |
| New results | Allowed at many venues within the rebuttal period; check rules on new figures, links, and revised PDFs |
| Anonymity | No identifying links or names |
| Discussion phase | Answer follow-up questions promptly and briefly |

## 5. Journal response letter mechanics

| Item | Practice |
|---|---|
| Cover note | Summary of main changes for the editor |
| Structure | Each comment quoted in full, then the response, then the change with location |
| Marking changes | Coloured text, highlighting, or a tracked-changes or latexdiff version, per the journal |
| Line numbers | Refer to the revised manuscript's line numbers |
| Tone | Courteous and complete; editors check that nothing was skipped |
| Disagreement | Allowed with evidence; the editor decides |

## 6. Concession and disagreement templates

**Partial concession:**
> We agree that <part the reviewer is right about>. We have <change>. However, <part we maintain>, because <evidence>; we have added <text> to clarify this.

**Disagreement:**
> We appreciate this point. Our analysis suggests otherwise: <evidence with numbers or citation>. To address the concern directly, we added <analysis or text> (Section x), which shows <...>.

**Infeasible request:**
> A full <experiment> would require <specific resource or time>. As a feasible proxy, we <alternative>, finding <result>. We have also narrowed the claim in Section x to <...>.
